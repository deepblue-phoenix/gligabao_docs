Configuration is read from `bin/gligabao.toml` (override with `--config`).

## Settings

| Key | Default | Purpose |
| --- | --- | --- |
| `port` | `7878` | HTTP port |
| `anthropic_api_key` | `ANTHROPIC_API_KEY` | LLM for remember/recall |
| `openai_api_key` | `OPENAI_API_KEY` | Embeddings (without it no vectors are stored) |
| `pinecone_api_key` | `PINECONE_API_KEY` | Hosted vector store |
| `db_backend` | `"sqlite"` | `"sqlite"` or `"postgres"` (with `postgres_dsn`), see [Database](/getting-started/database) |
| `vector_store` | `"chromem"` | `"chromem"` (embedded) or `"pinecone"` (hosted) |
| `embedding_dimensions` | `1536` | Vector size |
| `pinecone_index_host` | `PINECONE_INDEX_HOST` | Data-plane host of the Pinecone index |
| `chunk_size` | `1024` | Tokens per chunk, see [Chunking](/guides/chunking) |
| `chunk_overlap_percent` | `20` | Overlap between chunks |
| `jev_api_key` | `JEV_API_KEY` | Enables Jev, TypeSafe's system 1 model (`jev_base_url` and `jev_model` are optional overrides) |
| `sidecar_url` | `SIDECAR_URL`, else `http://127.0.0.1:8787` | Base URL of the Python sidecar's REST API, the only service the Go server calls for [training jobs](/training/overview); the sidecar proxies to Modal |
| `eval` | `false` | Register the eval endpoints |
| `admin_ui` | `false` | Serve the admin panel |

<Note>
  The chromem store fixes the embedding size when its directory is created, and a Pinecone index must match it. Details: [Vector storage](/guides/vectors).
</Note>

## Prices

A `[prices."<model-prefix>"]` table (`input`, `output`, optional `cache_write`/`cache_read`, USD per 1M tokens) overrides or extends the built-in model prices used to compute the cost of each LLM call; the longest matching prefix wins.

```toml
[prices."claude-haiku"]
input = 1.0
output = 5.0
```

Every model invocation (LLM call, embedding request, web search, Jev classification) is a row of the `gb_model_runs` table, with the model, the thinking level, the tokens and the cost. See [Model runs](/operations/model-runs).

## Jev

When a Jev key is set, `remember` first classifies the text as simple/medium/complex in the number of entities it will yield and logs it with Jev's confidence and the call's latency. See [Remember](/api-reference/remember).

## Eval mode

With `serve --eval` (or `eval = true`) the server also registers `POST /v1/gb/eval/remember` and `POST /v1/gb/eval/recall`. They take the same bodies as the regular endpoints, record the call as an [ATIF](https://github.com/laude-institute/harbor) trajectory, store it as pretty-printed JSON in an `atif/` directory next to the SQLite file, and return the full `trajectory` (and its `trajectory_id`) in the response. They are not registered otherwise, and the regular endpoints never generate trajectories. `go run ./evals` runs through these endpoints (`-atif <dir>` also keeps the trajectories as files). See [Evals](/operations/evals).

## Admin UI

`admin_ui/` holds a small admin panel (TypeScript, SCSS, HTML). `./run_build.sh` builds it (needs node/npm) and embeds `admin_ui/dist` into the binary with `go:embed`; pass `--no-admin-ui` (or `BUILD_ADMIN_UI=false`) to skip it. With `admin_ui = true` (or `serve --admin-ui`; default `false`) the server serves it at `/v1/gb/admin/`. If the assets were not embedded, the server logs a warning and does not register the handlers.

The panel has views for the databases (main), evals, timeseries, model runs, remember runs and **training**: the training view uploads training datasets and runs Gemma-4 fine-tuning jobs on the sidecar, with a dataset picker, the list of jobs, a live event feed and a loss graph (see [Training](/training/overview)). It needs `sidecar_url` to reach the sidecar, which proxies to Modal. A `sidecar: up` / `sidecar: down` badge in the top bar shows whether the sidecar answers its health check.
