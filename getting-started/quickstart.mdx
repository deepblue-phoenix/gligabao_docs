## 1. Build and run

gligabao is pure Go and builds with `CGO_ENABLED=0`, so no C compiler is needed.

```sh
./run_build.sh                      # builds bin/gligabao
export ANTHROPIC_API_KEY=...        # required for remember/recall
./bin/gligabao serve                # listens on :7878 by default
```

<Tip>
  Prefer containers? `docker compose up --build` starts the server on `localhost:7878` and the [Python sidecar](/operations/sidecar) on `localhost:8787`, on one Docker network (the server talks only to the sidecar, which needs Modal tokens to proxy training calls to Modal). Set `ANTHROPIC_API_KEY` (and optionally `OPENAI_API_KEY`) in your shell first; data is kept in the `gligabao-data` volume.
</Tip>

<Tip>
  Run `./run_tests.sh` to run the test eval. Plain `go build ./cmd/gligabao` and `go test ./...` also work.
</Tip>

## 2. Remember something

```sh
curl -X POST localhost:7878/v1/gb/remember \
  -H 'content-type: application/json' \
  -d '{"user_id": "u1", "text": "Alice works at Acme and lives in Paris."}'
```

The response contains the `artifact_id`, the extracted entities, the `edges` with their temporal fields and any `invalidated_edges`. See [Remember](/api-reference/remember).

## 3. Recall

```sh
curl -X POST localhost:7878/v1/gb/recall \
  -H 'content-type: application/json' \
  -d '{"user_id": "u1", "query": "Where does Alice work?"}'
```

You get an `answer` plus the `evidence` (entities and edges) it relied on. See [Recall](/api-reference/recall).

## 4. Inspect the graph

```sh
curl 'localhost:7878/v1/gb/datasets/main/graph?user_id=u1'
```

See [Graph export](/api-reference/graph).
