## Long-term memory for your AI application

gligabao is a small, self-hosted MCP/HTTP server: use it over its HTTP API, or as an MCP server for Claude, Claude Code and other MCP clients. You send it free-form text; it turns that text into a knowledge graph. Later you ask questions in natural language and it answers from what it stored, **citing the facts it used**.

## The two core calls

<CodeGroup>
```sh Remember
curl -X POST localhost:7878/v1/gb/remember \
  -H 'content-type: application/json' \
  -d '{"user_id": "u1", "text": "Alice works at Acme and lives in Paris."}'
```

```sh Query
curl -X POST localhost:7878/v1/gb/query \
  -H 'content-type: application/json' \
  -d '{"user_id": "u1", "query": "Where does Alice work?"}'
```
</CodeGroup>

<Steps>
  <Step title="Remember">
    An LLM extracts *entities* and *edges* (relations such as `works_at`) from the text. Entities are deduplicated, and each fact is anchored to the artifact it came from and records when it was true.
  </Step>
  <Step title="Query">
    The query finds relevant entities and facts, by keywords and by the similarity of their embeddings; the surrounding subgraph of live facts is expanded by one hop, the chunks of long texts that are close to the question are added as passages, and an LLM answers using only that context. The response includes the evidence behind the answer.
  </Step>
  <Step title="Store">
    SQLite (a single file, the default) or PostgreSQL, plus an embedded or hosted vector store.
  </Step>
</Steps>
