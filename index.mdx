## Long-term memory for your AI application

gligabao is a small, self-hosted HTTP service. You send it free-form text; it turns that text into a knowledge graph. Later you ask questions in natural language and it answers from what it stored, **citing the facts it used**.

## The two core calls

<CodeGroup>
```sh Remember
curl -X POST localhost:7878/v1/gb/remember \
  -H 'content-type: application/json' \
  -d '{"user_id": "u1", "text": "Alice works at Acme and lives in Paris."}'
```

```sh Recall
curl -X POST localhost:7878/v1/gb/recall \
  -H 'content-type: application/json' \
  -d '{"user_id": "u1", "query": "Where does Alice work?"}'
```
</CodeGroup>

<Steps>
  <Step title="Remember">
    An LLM extracts *entities* and *edges* (relations such as `works_at`) from the text. Entities are deduplicated, and each fact is anchored to the artifact it came from and records when it was true.
  </Step>
  <Step title="Recall">
    The query finds relevant entities, the surrounding subgraph is expanded by one hop, and an LLM answers using only that context. The response includes the evidence behind the answer.
  </Step>
  <Step title="Store">
    SQLite (a single file, the default) or PostgreSQL, plus an embedded or hosted vector store.
  </Step>
</Steps>
